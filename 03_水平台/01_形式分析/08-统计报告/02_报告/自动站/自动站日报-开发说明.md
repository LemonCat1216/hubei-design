# 自动站日报开发说明

本文面向维护 `智能报告-自动站.html`、`report-data.js` 和导出脚本的开发人员，目标是让日报在常规数据、缺数数据、特殊地市数据等场景下都能稳定生成。

## 目录与职责

- `智能报告-自动站.html`
  - 报告模板、分页逻辑、浏览器内 PDF/Word 导出按钮。
- `report-data.js`
  - 报告数据源，页面渲染完全依赖 `window.__REPORT_DATA__`。
- `export-wysiwyg-pdf.mjs`
  - 外部脚本导出 PDF。
  - 未显式传入输出文件名时，默认导出为正式命名文件：`<title>（<reportDate>）.pdf`。

## 标准导出方式

在当前目录执行：

```powershell
node .\export-wysiwyg-pdf.mjs .\智能报告-自动站.html
```

默认会生成类似文件：

```text
湖北省地表水水质自动站日报（2026年6月10日）.pdf
```

如果需要另存为其他路径或名称：

```powershell
node .\export-wysiwyg-pdf.mjs .\智能报告-自动站.html .\自定义名称.pdf
```

## 正式命名规则

- 文件主标题取自 HTML 的 `<title>`。
- 日期优先取 `report-data.js` 中的 `D.meta.reportDate`。
- 如果 `reportDate` 缺失，则回退读取 `D.meta.dateISO` 并转成 `YYYY年M月D日`。
- Windows 非法文件名字符会自动替换为 `_`。

建议始终同步维护以下两个字段，避免标题与正文不一致：

```js
D.meta = {
  reportDate: "2026年6月10日",
  dateISO: "2026-06-10"
};
```

```html
<title>湖北省地表水水质自动站日报</title>
```

## `report-data.js` 数据结构约定

### 1. 基础元信息

`D.meta` 至少应包含：

- `reportDate`
- `dateISO`

页面首页日期、导出正式命名都依赖这两个字段。

### 2. 总体统计

`D.summary`、`D.qualityDist`、`D.pollutionFactors` 用于首页概述区。

维护时需要重点保证：

- `summary.totalValid`、`summary.noData` 与附表数据口径一致。
- `summary.national`、`summary.provincial` 的 `total/compliant/nonCompliant` 自洽。
- `qualityDist` 中各等级数量之和应与对应 `total` 一致。
- `pollutionFactors.factors` 建议按出现次数倒序，避免图表比例失真。

### 3. 重点关注自动站

涉及以下区块：

- `focusClass5`
- `calendarExceed`
- `continuousNonCompliance`

维护要求：

- `focusClass5.count` 应与 `stations.length` 保持一致。
- `calendarExceed[].calendar` 固定按近 30 天组织，单元项格式如下：

```js
{ day: 9, cls: "Ⅳ类", level: 4 }
```

- 无超标日时保留空值：

```js
{ day: 10, cls: "", level: "" }
```

- `continuousNonCompliance[].detail` 必须按日期升序，便于表格阅读。

### 4. 地市段落

`D.cities` 分两类：

- 常规地市：直接使用 `name/nationalCount/provincialCount/goodCount/nonCompliantCount/stations`
- 特殊分组：使用 `isSpecial: true` 和 `subCities`

特殊分组当前用于“省直管县市及林区”，推荐结构：

```js
{
  name: "省直管县市及林区",
  isSpecial: true,
  subCities: [
    {
      name: "仙桃市",
      provincialCount: 5,
      nonCompliantCount: 1,
      nonCompliantStations: [
        { name: "姚嘴王岭村", cls: "Ⅲ类" }
      ]
    }
  ]
}
```

如果某个子地区无不达标站，也请显式写空数组：

```js
nonCompliantStations: []
```

这样模板会自动输出“当日无不达标自动站”，不会出现 `undefined` 或缺句。

### 5. 附表数据

附表依赖以下数组：

- `exceedReport`
- `exceedData`
- `compliantReport`
- `compliantData`
- `noData`

维护要求：

- 汇总表和明细表应使用同一批站点，避免“汇总有、明细无”。
- `compliantData` 因模板会额外展示“监测时间”，每条记录必须有 `date`。
- `noData` 即使没有缺数站，也建议保留一条说明型记录，或者直接传空数组。

推荐空数组场景：

```js
D.noData = [];
```

此时页面会自动显示“当日未发现无监测数据自动站”。

## 常见数据场景处理建议

### 场景 1：当天所有站点都达标

建议：

- `summary.dailyExceed = 0`
- `focusClass5.stations = []`
- `calendarExceed = []`
- `continuousNonCompliance = []`
- `pollutionFactors.factors = []`

模板已经对这些空数组做了兜底，会输出说明文字。

### 场景 2：存在无监测数据站点

建议：

- `summary.noData` 与 `D.noData.length` 保持一致。
- `D.noData[]` 中补全 `station/city/target/date/note`。
- `summary.totalValid` 只统计有效监测记录，不要把缺数站混入。

### 场景 3：省直管县市或其他特殊行政分组

建议：

- 使用 `isSpecial: true`。
- 不要强行塞进常规 `stations` 文案结构，否则段落语义不自然。
- `nonCompliantStations` 建议显式列出站点名和类别，方便报告直接成文。

### 场景 4：近 30 日中既有 `Ⅳ类` 也有 `Ⅴ类/劣Ⅴ类`

建议：

- 严格填写真实等级，不要全部写成 `劣Ⅴ类`。
- `level` 与 `cls` 必须匹配：
  - `Ⅳ类 -> 4`
  - `Ⅴ类 -> 5`
  - `劣Ⅴ类 -> "bad-5"`

否则日历着色会失真，也会误导连续超标判断。

### 场景 5：没有任何可展示附表数据

模板已有空数据兜底，但仍建议保留主结构：

```js
D.exceedReport = [];
D.exceedData = [];
D.compliantReport = [];
D.compliantData = [];
D.noData = [];
```

不要删除字段本身，避免后续维护者误判为字段名变更。

## 维护检查清单

每次更新数据后，至少核对以下内容：

- `<title>` 是否仍为正式报告名称。
- `D.meta.reportDate` 与 `D.meta.dateISO` 是否同步。
- 首页统计数是否与附表明细口径一致。
- `count` 字段是否与对应数组长度一致。
- 特殊地市是否补了 `nonCompliantStations`。
- 浏览器预览分页是否正常。
- 脚本导出的 PDF 文件名是否为正式命名。

## 建议的更新流程

1. 先更新 `report-data.js`。
2. 浏览器打开 `智能报告-自动站.html` 检查正文、表格、分页。
3. 运行 `node .\export-wysiwyg-pdf.mjs .\智能报告-自动站.html`。
4. 检查输出 PDF 名称、页数、表格换页、首页标题是否正确。

## 当前实现说明

- 页面文案已经针对空数组做了兜底，不需要再在数据层拼接“暂无数据”字符串。
- PDF 脚本导出依赖本机 Chrome 或 Edge。
- 若脚本未找到浏览器，可通过环境变量 `CHROME_PATH` 指定浏览器可执行文件。
